pg-quick-sync

Ergonomic PostgreSQL extension for managing postgres_fdw connections via URIs and incremental data synchronization.

Get Started View on GitHub
Quick Install & Enable 
# 1. Build and install extension files
make install

# 2. In PostgreSQL (psql): enable extension and dependencies
create extension quick_sync cascade;
PostgreSQL 13+ Zero Plaintext Passwords in Custom Tables Fast Batch Defaults (fetch_size = 50000)

Overview & Key Features

Managing foreign servers and user mappings in vanilla PostgreSQL requires repetitive, boilerplate DDL statements. pg-quick-sync wraps postgres_fdw in a clean, programmatic interface with performance best practices baked in.

URI-Based Setup

Configure foreign servers and user mappings with a single PostgreSQL connection string (postgres://user:pass@host:port/dbname). No manual regex or split DDL necessary.

Safe Credential Inventory

Connection topology and metadata are cleanly logged in quick_sync.connections, but plaintext passwords are never stored in user tables. They remain secured inside PostgreSQL's native user mappings.

Full Connection CRUD

Complete programmatic lifecycle: create_connection(), inspect status via list_connections(), perform granular rotations with edit_connection(), and tear down with delete_connection().

Tuned FDW Defaults

Foreign servers are generated with production-ready options: fetch_size = 50000 for massive network roundtrip reduction, and use_remote_estimate = true so PostgreSQL plans join queries intelligently.

Installation

Install the extension on any host running PostgreSQL 13 or newer.

Prerequisites:
  • PostgreSQL 13+ with development headers (postgresql-server-dev-* or Homebrew PostgreSQL).
  • postgres_fdw contrib module available in your PostgreSQL installation.
  • Standard build toolchain (make, gcc or clang).

1 Clone the Repository & Build

Terminal (Bash) 
git clone https://github.com/angelmorgaldev/pg-quick-sync.git
cd pg-quick-sync
make install

Note: Depending on your system permissions, you may need sudo make install.

2 Enable the Extension in your Database

psql / SQL 
-- Enable postgres_fdw and quick_sync together
create extension quick_sync cascade;

3 Verify Installation

psql / SQL 
-- Confirm functions are loaded and catalog is accessible
select * from quick_sync.list_connections();
Module: Connection Management

API Reference (v0.1.0)

Complete specification of the connection CRUD API. All routines run inside the dedicated quick_sync schema with full atomic transaction support.

quick_sync.create_connection

PL/pgSQL returns text

Parses a standard PostgreSQL connection URI, automatically instantiates an optimized foreign server (qsync_srv_<alias>), configures the user mapping for current_user, and logs non-sensitive topology metadata into quick_sync.connections.

Signature
quick_sync.create_connection(
    p_alias      text,
    p_uri        text,
    p_fetch_size int default 50000
) returns text;

Parameters

Name Type Default Description
p_alias text required Unique connection identifier (must be lowercase alphanumeric + underscores, regex ^[a-z_][a-z0-9_]*$).
p_uri text required Standard URI: postgres://user:password@host:port/dbname.
p_fetch_size int 50000 Batch row fetch size for postgres_fdw foreign table scans.

Runnable Example

-- Register a remote analytics warehouse connection
select quick_sync.create_connection(
    'analytics_dw',
    'postgres://etl_user:S3cureP@ss!@dw.internal.acme.com:5432/analytics_production'
);

-- With custom batch fetch size for high throughput pipelines
select quick_sync.create_connection(
    'stripe_replica',
    'postgres://reader:Secret#99@db.replica.cloud:5432/finance_db',
    p_fetch_size => 100000
);

quick_sync.list_connections

SQL / STABLE returns table

Returns all registered connection aliases, validating the live existence of the backing foreign server in PostgreSQL's catalog (pg_foreign_server) and calculating the active foreign table count.

Signature
quick_sync.list_connections()
returns table (
    alias          text,
    server_name    text,
    host           text,
    port           int,
    dbname         text,
    remote_user    text,
    fetch_size     int,
    foreign_tables bigint,
    is_active      boolean,
    updated_at     timestamptz
);

Output Columns

Column Type Description
alias text Primary alias identifier registered by the user.
server_name text Internal Postgres foreign server name (qsync_srv_<alias>).
host text Remote database hostname or IP address.
port int Remote port (defaults to 5432).
dbname text Remote target database name.
remote_user text Remote authentication username.
fetch_size int Configured batch fetch size.
foreign_tables bigint Current count of foreign tables associated with this server.
is_active boolean true if foreign server exists in pg_foreign_server.
updated_at timestamptz Timestamp of last creation or edit mutation.

Runnable Example & Sample Result

-- Query connection status
select 
    alias, 
    host, 
    dbname, 
    remote_user, 
    fetch_size, 
    foreign_tables, 
    is_active 
from quick_sync.list_connections();

-- Sample Output:
--      alias     |         host         |        dbname        | remote_user | fetch_size | foreign_tables | is_active 
-- ----------------+----------------------+----------------------+-------------+------------+----------------+-----------
--  analytics_dw   | dw.internal.acme.com | analytics_production | etl_user    |      50000 |              4 | t
--  stripe_replica | db.replica.cloud     | finance_db           | reader      |     100000 |              0 | t

quick_sync.edit_connection

PL/pgSQL returns text

Updates connection credentials, network destination, or fetch performance. Supports both full URI replacement and granular named-parameter updates (e.g., zero-downtime password rotation or host failover).

Signature
quick_sync.edit_connection(
    p_alias      text,
    p_uri        text default null,
    p_host       text default null,
    p_port       int  default null,
    p_dbname     text default null,
    p_user       text default null,
    p_password   text default null,
    p_fetch_size int  default null
) returns text;

Parameters

Name Type Default Description
p_alias text required Alias of the existing connection to modify.
p_uri text null Optional full URI string to replace all connection properties simultaneously.
p_host text null New hostname (alters alter server option).
p_port int null New remote port number.
p_dbname text null New remote database name.
p_user text null New username in the user mapping.
p_password text null New password (rotates credential in user mapping; never logged to metadata table).
p_fetch_size int null New FDW fetch_size parameter on the foreign server.

Common Use Case Examples

1. Password Rotation (Zero Downtime) 
-- Safely update remote credentials without altering host or metadata
select quick_sync.edit_connection(
    'analytics_dw', 
    p_password => 'N3w_R0tated_S3cret_2026!'
);
2. Host & Port Failover 
-- Switch target replica endpoint following database migration
select quick_sync.edit_connection(
    'analytics_dw', 
    p_host => 'replica-02.internal.acme.com', 
    p_port => 5433
);
3. Full URI Replacement 
-- Completely re-point connection to a new environment via connection string
select quick_sync.edit_connection(
    'analytics_dw', 
    p_uri => 'postgres://analyst:secret@dw-staging.acme.internal:5432/staging_dw'
);
4. Performance Batch Size Tuning 
-- Increase FDW cursor fetch size to 100,000 for heavy analytical scans
select quick_sync.edit_connection(
    'analytics_dw', 
    p_fetch_size => 100000
);

quick_sync.delete_connection

PL/pgSQL returns text

Drops user mappings, drops the backing foreign server, and removes the entry from the quick_sync.connections registry table. Includes cascade support to safely purge or retain mapped foreign tables.

Signature
quick_sync.delete_connection(
    p_alias   text,
    p_cascade boolean default true
) returns text;

Parameters

Name Type Default Description
p_alias text required Alias of the connection to remove.
p_cascade boolean true When true, drops foreign server with cascade (removing dependent foreign tables). When false, raises an error if foreign tables still depend on it (restrict).

Runnable Example

-- Default: Clean teardown (cascades and drops any linked foreign tables)
select quick_sync.delete_connection('analytics_dw');

-- Restrict: Safeguard deletion (raises exception if foreign tables still exist)
select quick_sync.delete_connection('analytics_dw', p_cascade => false);

Catalog & Security Architecture

How pg-quick-sync maintains state and enforces database security best practices.

quick_sync.connections

Internal metadata table created automatically upon extension loading. Keeps track of connection topology and sync parameters: 

create table if not exists quick_sync.connections (
    alias        text primary key,
    server_name  text unique not null,
    host         text not null,
    port         int  not null default 5432,
    dbname       text not null,
    remote_user  text not null,
    fetch_size   int  not null default 50000,
    created_at   timestamptz not null default now(),
    updated_at   timestamptz not null default now()
);

Safe Credential Guarantee

Notice that quick_sync.connections does not contain a password column. When you pass a connection URI or password to create_connection() or edit_connection():

  • The password is sent directly to PostgreSQL's native catalog via create user mapping for current_user server ... options (user, password).
  • Only authorized database superusers or mapping owners can query encrypted credentials via pg_user_mappings.
  • Standard users reading quick_sync.list_connections() will never see plaintext passwords exposed in application dumps or monitoring queries.
